# Changelog — web

All notable changes to the `web` component. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions are `MAJOR.MINOR.BUGFIX.BUILD` (ADR-0015).

## [Unreleased]

### Added
- Restore wizard (`/recovery-points/[id]/restore`, `restore.execute` + `backup.read`), launched with "Restore…" from a committed recovery point's detail page and from committed rows of the application's Backups tab and the Recovery points page. **Target**: host (default the source host; other active hosts with `host.read`), components from the manifest (default every captured component except fsmeta / image; failed ones disabled; fsmeta shown as "included automatically" under its parent) and a bind-mount / project path remap editor (from → to rows, validated like the server; suggestions prefilled when an alternate host is chosen). **Impact preview** (`restore-preview`, re-run whenever the target, components or remaps change): mode badge (In place / Alternate host), red production banner with the reasons, blocking collisions (kind, name, detail) in red, warnings in amber, data per component (Overwrite / Create / Restore files / Load dump, target, size), containers to stop and to re-create, networks, images (pull by digest) and published ports; a blocked preview cannot continue. **Confirm**: the safety model in one paragraph, a reason (required for production), and for production a typed confirmation ("Type <application name> to confirm", exact match) — Start stays disabled until every safeguard holds, and explains why when `restore.production` is missing. Success opens the restore; 409 / 403 / 400 are explained in place.
- Restores page (`/restores`, `restore.read`): recovery history with application, recovery point, target host, mode, production flag, state (running blue with the current step, succeeded green, rolled back amber, failed red, with the error), requested by, created and duration; application and state filters kept in the URL; refreshes every 3 s while a restore runs, otherwise every 15 s.
- Restore detail (`/restores/[id]`): state, mode and production badges, a step progress indicator (grant-access → agent-access → images → stop-application → restore-data → recreate-containers → start-application → restore-database → health-check → commit; steps that do not apply to the recorded preview are left out; the step a failed or rolled-back restore stopped at is marked), polling every 3 s while running; summary with the reason, components and path remaps; the result (component outcomes with target and previous paths, metadata applied and verify mismatches, re-created containers, images, databases, health per container with an expandable log tail, rollback outcome) and the preview recorded at request time (same component as the wizard, read-only).
- Application detail: **Restores** tab (`restore.read`) with that application's restores. Dashboard: **Recent restores** card (running and failed / rolled-back counts, latest three).
- Navigation entry for Restores (`restore.read`).
- Zod schemas, client functions, query keys and hooks for the Restores operations (`src/lib/api/restore-schemas.ts`; the untyped `result` and `path_remaps` of a run are parsed leniently); pure helpers for component selection, remap suggestions / validation, the Start safeguards, the step indicator and durations (`src/lib/restore.ts`).
- Mock API (`scripts/mock-restore.mjs`): previews computed from the mock manifests — a clean in-place production restore on docker-prod-01, collisions (container name, port, volume, bind path unless remapped) on docker-edge-02 and a clean alternate-host restore on the new active host docker-dr-03 (added to `mock-fleet.mjs`); start enforces the collision, `restore.production`, confirmation and reason rules and one operation per application; started runs move through their steps over ~15 s and succeed; seeded history with a failed (image pull denied), a rolled-back (health check failed, with a PostgreSQL log tail) and a succeeded restore. The master admin gets `restore.read` / `restore.execute`; the OIDC user gets `restore.read` / `restore.execute` without `restore.production` (like a Restore Operator).
- Tests: restore schemas, component selection, remap suggestions / validation / editor, typed-confirmation, reason and production-permission gating, collisions blocking the wizard, the step indicator, durations, state badges, the preview sections, the wizard flow against a mocked fetch (request bodies, re-run on changes, 409), restore detail (running / rolled back with log tail / failed), restore lists, dashboard card and the Restore… launch points (146 → 186 tests).
- Repositories page (`/repositories`, `repository.read`): status badge (**Escrow not confirmed** amber, Ready green, Unavailable red), backend, live storage health with a capacity bar (used / total, amber ≥ 80 %, red ≥ 90 %) or the reason the reposerver is unreachable, pinned certificate fingerprint (truncated, with copy), last reindex; refreshes every 30 s. For `repository.manage`: Reindex (confirmation dialog, toast with the workflow id), escrow package download (audited) and a "Confirm escrow" shortcut for Repositories awaiting escrow.
- Create Repository wizard (`repository.manage`): name, description, backend (NFS / filesystem), management URL (default `http://dbr2-reposerver:8091`), server URL, optional internal server URL (`https://dbr2-reposerver:51515` suggested; empty = server URL) and default flag; blocked with a link to the escrow recipients while fewer than two exist. Step 2 states the Repository is not usable yet and offers the escrow package as a file (`application/octet-stream`, `escrow_filename`) with offline-storage and `age -d -i <identity-file> <file>` instructions; step 3 takes the confirmation code (`XXXX-XXXX-XXXX-XXXX`, case-, space- and dash-insensitive) and makes the Repository ready. The package lives only in component state.
- Repository detail (`/repositories/[id]`): every field including the internal server URL, reposerver status (capacity, free space, Kopia version), **usage by host** (logical size of each application's latest recovery point; a tooltip explains that deduplicated physical usage is shared and not attributable) and, while awaiting escrow, the download + confirm flow.
- Escrow recipients section on the Repositories page: list (age / SSH key, shortened), add (key holder + public key) and remove (confirmation, warns when fewer than two would remain). A pasted private identity (`AGE-SECRET-KEY-…` or `… PRIVATE KEY`) is rejected client-side, cleared from the field immediately and never sent, with a warning to keep identities offline.
- Application detail: "Back up now" (`backup.execute`) with an optional one-off consistency mode; 409 is shown as "an operation is already running". New **Backups** tab (`backup.read`: recovery points with state, Complete / Partial, mode, crash-consistent flag, size, components, created / committed, error) and **Backup settings** tab (`policy.read` read-only, `policy.manage` to edit): Repository (default or a ready one), consistency mode (Automatic / Live / Quiesced / Offline, with explanations), maximum quiesce in minutes (1–1440, stored in seconds; unchanged minutes keep the stored seconds), pre-/post-hooks editor (container with suggestions, command typed as one line and split shell-like into argv with a preview, timeout, optional) and optional / excluded components (`config`, `volume:<name>`, `bind:<source>` derived from the analysis like the server's backup plan).
- Recovery points page (`/recovery-points`, `backup.read`): all applications, application and state filters kept in the URL, refreshes every 15 s; recovery point detail (`/recovery-points/[id]`) with summary, the manifest's component table (name, kind, required, status, size, files, snapshot, source, SELinux context, owner) and a collapsible raw manifest JSON viewer with copy.
- Alerts page (`/alerts`, `backup.read`): most severe first, optional acknowledged alerts, links to the recovery point / application / Repository / host, acknowledge for `backup.execute`; dashboard **Alerts** card with open alerts by severity (critical in red) and the latest three.
- Host detail: **Limits** card (`host.read`, edit with `host.manage`): maximum concurrent jobs, backup window as HH:MM time inputs ↔ minutes of the day (wrapping midnight), "no window" toggle and an IANA timezone input; notes that saving makes the agent reconnect.
- Navigation entries for Repositories (`repository.read`), Recovery points and Alerts (`backup.read`); the nav scrolls horizontally on narrow screens.
- Zod schemas, typed client functions, query keys and hooks for the Repositories, Backups and host-limit operations (`src/lib/api/protection-schemas.ts`); pure helpers for HH:MM, shell-like command splitting, component derivation and file downloads (`src/lib/protection.ts`).
- Mock API (`scripts/mock-protection.mjs`): two escrow recipients; a ready default, an awaiting-escrow (code `K7QX-M2DA-PL4W-ZT6R`) and an unreachable Repository with `internal_server_url` and `usage_by_host`; recovery points committed / partial / failed / in progress / missing with volume, fsmeta, bind-mount and config manifest components; four alerts; host limits; create (409 below two recipients), escrow confirm, reindex, back up now (409 while one runs), backup settings and acknowledge. The master admin gets the backup, policy and repository permissions; the OIDC user is read-only for them.
- Tests: confirmation-code normalisation, minutes ↔ HH:MM, hook command splitting / joining, component derivation, private-key rejection, status and severity badges, capacity bar, the full create wizard, reindex confirmation, backup settings (read-only and save), Back up now 409, recovery point detail and manifest viewer, alerts (sorting, links, acknowledge, dashboard card), host limits and permission gating (78 → 146 tests). `vitest.setup.ts` stubs `ResizeObserver` for Radix.

### Added
- Hosts page (`/hosts`, `host.read`): TanStack Table of agents with status, live connection, agent version (+ outdated), OS/arch, Docker reachability, latency, last seen and certificate expiry; refreshes every 15 s. For `host.manage`: Approve / Suspend / Resume / Revoke with a required audit reason (Revoke also requires typing the hostname, ADR-0014), "Run discovery" (toast with the workflow id), "Add host" (registration token; join command, CA fingerprint and gateway shown once, with install steps) and a collapsible registration-token list with revoke.
- Host detail (`/hosts/[id]`): every agent field, the last status reason, and the inventory summary (engine, root dir, storage driver, SELinux, rootless, resource counts, discovery warnings); link to the host's applications.
- Applications page (`/applications`, `application.read`): kind, **Original / Reconstructed** definition badge, resource counts, high-severity unprotected-data warning, dependencies, secrets, ownership, last seen / missing; filters for host, kind and "only with unprotected data" (kept in the URL). For `application.manage`: "Group containers" (manual application from standalone containers) and delete for manual applications.
- Application detail (`/applications/[id]`): **Unprotected data** first (high before low), services and containers, volumes with class (Local / External / Ephemeral) and reasons, bind mounts, tmpfs, networks, images (digests, platform, "no registry digest" for local builds), dependencies, per-container env (secrets arrive masked) / ports / mounts, and an edit-metadata dialog (display name, owner, environment, criticality; only changed fields are sent).
- Compose tab: original Compose and `.env` files (masked) or the reconstructed YAML; "Reveal secrets" for `secrets.read` behind an audited-action confirmation. Revealed content uses its own query key with `gcTime: 0`, is never refetched automatically and is dropped when hidden or on unmount.
- Dashboard "Protection overview" card (applications, with unprotected high-severity data, reconstructed definitions, hosts pending approval).
- Navigation entries for Hosts and Applications, shown only with `host.read` / `application.read`.
- Zod schemas and typed client functions for the Hosts and Applications operations of `api/openapi.yaml` (nullable arrays normalised to `[]`); `actionErrorMessage` for 409 `conflict`, 400 `validation_failed` (with field errors) and 403 `forbidden`.
- In-house toast notifications (no new dependency); shadcn/ui `dialog`, `select`, `tabs`, `collapsible`, `checkbox` and `textarea`.
- Mock API: Hosts and Applications endpoints (`scripts/mock-fleet.mjs`) with hosts in every state, an application with unprotected data, a reconstructed one, a manual one and a missing one, masked and revealed Compose responses; the mock OIDC user is now read-only for hosts and applications.
- Tests: schema fixtures, unprotected-data sorting, the Reconstructed badge, the reveal flow and its permission, the revoke hostname confirmation and the show-once join command.
- Component scaffold (Phase 1).
- Next.js 16.3 console (App Router, TypeScript strict, `output: "standalone"`) with React 19.2, Tailwind CSS 4.3, shadcn/ui (Radix, light and dark themes), TanStack Query 5, TanStack Table 9 and Zod 4.
- Same-origin API proxy (`/api/*` → `DBR2_API_INTERNAL_URL`, resolved per request): streams bodies, forwards cookies and the CSRF-relevant headers, sets `X-Forwarded-*`, returns every `Set-Cookie` unchanged and passes redirects through. Serves the backend's Swagger UI at `/api/docs`.
- Typed API client and Zod schemas for the Phase 1 contract; `application/problem+json` errors become a typed `ApiError` (with `code` and `Retry-After`).
- Sign-in page: master admin username and password, TOTP step on `totp_required`, locked and rate-limited messages using `Retry-After`, one button per OIDC provider ("Sign in with Microsoft" for Entra ID), open-redirect-safe `?return_to=` and `?error=` handling.
- Client-side auth guard on `/auth/me`, and an app shell with navigation (Dashboard, Audit, Settings), theme toggle and user menu with sign-out.
- Dashboard placeholder with roles, a link to the API docs and a platform status card (`/health/ready`).
- Security settings: change the master admin password; enroll TOTP (QR code rendered locally), confirm and disable.
- Audit log table with cursor-based "Load more" (requires `audit.read`).
- Version footer on every page (console `NEXT_PUBLIC_DBR2_VERSION` and platform version) and an About page listing every component version (ADR-0015).
- Multi-stage `Dockerfile` (digest-pinned `node:22.23.3-alpine3.24`, non-root, `ARG BUILD`, version `$(cat VERSION).$BUILD`) and `.dockerignore`.
- Mock of the Phase 1 API (`npm run mock-api`) for development without the Go backend.
- Vitest unit tests for the `return_to` sanitizer, API error handling, the version footer, the TOTP login step and the proxy's header and cookie forwarding.

### Notes
- In the Compose deployment, browsers reach `/api/*` through the Caddy edge proxy, which discards client-supplied `X-Forwarded-*`. The console's own `/api` proxy is for development: a Next.js route handler cannot see the socket address, so it cannot sanitize a client-supplied `X-Forwarded-For`.

### Security
- Security headers on console pages (`X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: same-origin`, COOP, `Permissions-Policy`); `X-Powered-By` disabled.
- System font stacks only, so nothing is fetched from third-party hosts at build or run time.
