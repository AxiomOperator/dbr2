### Added
- **Phases 7–9 — web console.**
- **Policies** (`/policies`, `/policies/[id]`; `policy.read`, changes with `policy.manage`) replace the placeholder: list with the schedule in words over its cron expression and timezone, next run, retention summary and how far back it reaches, default mode / Repository, applications count and Enabled / Disabled; create / edit dialog with presets (hourly, daily, weekly, monthly) or a custom 5-field cron with a live plain-language preview and field-level error (the server's validation message is shown when it disagrees), timezone picker, grandfather-father-son retention fields with an explanation and a live summary ("the latest recovery point is never deleted"), consistency mode and Repository defaults; delete with a confirmation; detail with schedule, retention and assigned applications.

SMTP relay form (TLS mode, sender, username) with a write-only password (keep / replace / remove).
- **Verification** (Phase 9): recovery point detail verification card (state, last check, read share, per-component files / directories / files read / bytes read and errors) with "Verify now"; verification badges in recovery point tables; Repositories list / detail "Verify now" with an optional read percentage and "Last verified".

- Mock API: `scripts/mock-policies.mjs` (policies with cron validation and timezone-aware next run, assignments, contracts evaluated on read, deletion / undelete of recovery points and Repositories, notification channels, deliveries, test, SMTP) and `scripts/mock-platform.mjs` (verification, escrow health / regenerate / drills, platform backups, System Repository); seeds include a violated contract, a scheduled deletion, a verification failure with errors, unhealthy escrow, a failed webhook delivery and a partial platform backup; verification and deletion publish `backup.updated`, verification failures `alert.created`. - Tests: schedule presets / cron parsing and descriptions / retention summaries, event patterns and wildcard matching, write-only secret semantics, policy form (preview, API error, request), policy assignment, contract card and list, typed-confirmation deletion and undelete (recovery points and Repositories), channel form / event picker / send test / deliveries, SMTP, escrow health fixes, regenerate and drill flows, verification card, platform page (265 → 312 unit tests); Playwright: create policy + assign, delete with grace + undelete, notification channel create + test, escrow drill, and the new pages (10 → 14 tests).

### Added
- **Phase 6 — web console.** Navigation as a grouped, collapsible, permission-gated sidebar (Dashboard · Docker: Hosts, Applications, Containers, Volumes · Protection: Policies, Jobs, Recovery Points · Recovery: Restore, Restore Testing · Storage: Repositories, Usage · System: Agents, Users, Notifications, Audit Log, Settings); collapsed groups are remembered per browser, the group of the current page always stays open, a mobile menu replaces the sidebar on narrow screens and Notifications shows the number of open alerts.
- **OpenAPI-generated types and Zod schemas**: `@hey-api/openapi-ts` 0.99.0 (MIT, devDependency, `openapi-ts.config.ts`) generates `src/lib/api/generated/` from `../api/openapi.yaml` (`npm run generate:api`, `make web-generate`; header "Code generated … DO NOT EDIT."). The input is patched before generation: int64 stays a number, `format: uuid` is not enforced, nullable enums and `$ref` properties documented as "null when …" accept null. Every response is validated with the generated schemas through `contract()` (nullable / optional arrays → `[]`, unknown keys stripped); request bodies are validated with the form schema and the generated schema. The hand-written schema files are now thin layers over the generated ones (form schemas typed against the generated request types; the manifest and restore result stay lenient, untyped in the contract). `src/lib/api/generated.test.ts` fails when the committed output is stale; `src/test/mock-api-contract.test.ts` holds the mock API to the contract.
- **Protection status and coverage from the API** (`protection` of ApplicationSummary / ApplicationDetail): Applications list column (status badge, coverage "n/m components", Backing up / Restoring indicator) and a Protection filter kept in the URL; application detail **Protection card** (status, reasons, last backup linked to its recovery point, latest Complete / Partial and mode, last attempt and error, per-component coverage table, unresolved dependencies, live progress while an operation runs); the dashboard Protection overview counts applications by status (linked to the filtered list) and running operations.
- **Live updates over Server-Sent Events**: one shared `EventSource` (`LiveEventsProvider` in the console layout) on `GET /api/v1/events`; payloads validated with the generated schemas; each event invalidates the affected queries (coalesced), `agent.status` patches connection badges in place, `alert.created` raises a toast; re-reads everything after each (re)connect, reconnects with exponential backoff (1 s … 60 s, jitter) when the server closes the stream, pauses after 30 s in a hidden tab; header indicator (Live / Connecting / Not live). "Back up now" keeps its dialog open with live per-component progress (component n of m, bytes hashed / uploaded, files) from `job.progress`; the Protection card, Jobs rows and the restore detail (restore-data step) show the same progress. The dev API proxy streams `text/event-stream` unbuffered (`Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`).
- **Containers** (`/containers`) and **Volumes** (`/volumes`) pages (`host.read`, TanStack Table): fleet-wide lists with filters for host, application (or none), state / class (Local, External, Ephemeral, Unused) and protection, kept in the URL, linked to hosts and applications.
- **Hosts** (`/hosts`) is now the Docker host inventory (OS, engine, connection, applications / containers / volumes counts); the agent lifecycle moved to **Agents** (`/agents`: status actions, versions, certificates, registration tokens, Add host).
- **Jobs** (`/jobs`, `backup.read`; restores with `restore.read`): backups and restores in one live list with type, state and application filters, links to the recovery point or restore, errors and durations.
- **Usage** (`/usage`, `repository.read`): every Repository's live capacity and the per-host logical usage (`usage_by_host`) with totals.
- **Users** (`/users`, `user.read`; changes with `user.manage`): users with sign-in kind, status, roles and their source (manual, Entra ID group, master admin), last sign-in; edit manual roles and enable / disable with an audit reason; roles reference; Entra ID group → role mappings (add, remove). The master admin cannot be changed.
- **Restore**: "Start a restore" (`/restores/new`) picks a committed recovery point for the wizard; restore detail can **cancel** a running restore (`POST /restores/{id}/cancel`, confirmation explaining the compensation) and shows the source hostname from the API.
- **Topology tab** on the application detail (`@xyflow/react` 12.12.0, MIT, loaded on demand): images → containers → volumes / bind mounts / tmpfs → networks and external dependencies in four fixed columns (readable for 1–20 containers), storage coloured by `protection.components` (protected, not protected, never backed up), external dependencies dashed, light / dark themes, with a text version for screen readers.
- **Recovery point browser**: Complete / Partial badge in the title and a banner (Partial lists what was not captured), fsmeta records nested under their parent component, a **Topology at capture time** card (containers, ports, mounts, networks, volumes, images from `manifest.topology`) and a **Databases** card (dump engine / format / service; explains that dumps arrive with Phase 8). Jobs link backups to their recovery point.
- **Restore Testing** placeholder page stating what arrives and what works today (no sample data).
- **Content-Security-Policy with nonces** (`src/proxy.ts`, Next.js 16 Proxy): a fresh nonce per request and `default-src 'self'; script-src 'self' 'nonce-…' 'strict-dynamic'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'` on console pages (`'unsafe-eval'` only under `next dev`); pages render dynamically and the nonce reaches next-themes' script; Zod runs `jitless` so it never probes `eval`.

### Changed
- `lib/protection.ts` no longer re-implements the server's backup plan (`backupComponents`, the skip-bind list): Backup settings list the components from `protection.components` plus configured optional / excluded names.
- Response validation follows the contract strictly (required fields, enums, date-times); the previous lenient defaults for missing fields are gone.
- Alerts are now **Notifications** (`/notifications`; `/alerts` redirects permanently). The Restores page is titled **Restore**; the dashboard's "Hosts pending approval" links to Agents.
- Dependencies: `@xyflow/react` 12.12.0 (production), `@hey-api/openapi-ts` 0.99.0 and `@playwright/test` 1.63.0 (development).

### Notes
- In the Compose deployment, browsers reach `/api/*` through the Caddy edge proxy, which discards client-supplied `X-Forwarded-*`. The console's own `/api` proxy is for development: a Next.js route handler cannot see the socket address, so it cannot sanitize a client-supplied `X-Forwarded-For`.
