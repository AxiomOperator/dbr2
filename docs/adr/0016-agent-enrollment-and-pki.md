# ADR-0016: Agent enrollment, PKI and the gateway endpoint

- **Status:** Accepted
- **Date:** 2026-09-25

## Context

Phase 2 needs a concrete trust model for the agents defined in ADR-0001 and ADR-0006. The open questions were:

- how a new host proves it may join;
- how it learns to trust the gateway;
- where the CA key lives;
- how certificates are renewed and revoked;
- how the gateway is reached;
- how dbr2-worker authenticates to the gateway.

## Decision

1. **DBR² agent CA.**
   - An ECDSA P-256 root, valid 10 years, created by dbr2-server on first start.
   - Stored in PostgreSQL (`pki_authorities`), with the private key sealed with AES-256-GCM under `DBR2_SECRET_KEY`. Stealing either the database or the secret key alone does not yield the key.
   - Key escrow follows ADR-0008.
   - Go standard library only; no custom cryptography.
2. **Registration tokens.**
   - Administrators (`host.manage`) create single-use tokens that expire (1 hour to 7 days, default 24 hours).
   - Only the SHA-256 hash is stored, the token is shown once, and it is claimed with a conditional update, so concurrent use is race-safe.
   - Creating, using, failing and revoking tokens is audited.
3. **Trust bootstrap by fingerprint pinning** (similar to `kubeadm join`):
   - The join command carries the gateway address, the token and the **SHA-256 fingerprint of the CA**.
   - The agent fetches the CA over TLS without verification, accepts it only if the fingerprint matches, then verifies every connection against it. No secret is sent before the gateway is authenticated.
4. **CSR flow.**
   - The agent generates its key locally; the private key never leaves the host.
   - The CA sets the subject and a `dbr2://agent/<id>` URI SAN, ignoring what the CSR requests, so an agent cannot claim another identity.
   - Certificates are client-auth only and valid for **90 days**.
   - Accepted keys: P-256, P-384, Ed25519, or RSA of at least 3072 bits.
5. **Approval.** Enrolled agents are **pending**. The gateway refuses their sessions (`pending_approval`, retry after 30 s) until an administrator approves them.
6. **Status and revocation are checked on every connection.** The certificate serial must be known and not revoked, and the agent must be active.
   - **Suspend** ends the session and refuses new ones.
   - **Revoke** is permanent: it revokes all certificates, and the host must enroll again with a new token.
   - Revocation checks use the database, not a certificate revocation list (CRL), because the gateway is the only relying party.
7. **Renewal.**
   - The agent renews after two-thirds of its certificate's lifetime, over mTLS, with a **fresh key**.
   - The gateway revokes the agent's older certificates when it issues a new one.
8. **Version enforcement (ADR-0015).**
   - The gateway rejects a `Hello` with a different agent-protocol MAJOR (`protocol_version_mismatch`).
   - Agents older than the server's agent version still connect but are flagged "outdated".
9. **Gateway endpoint.**
   - The gateway's gRPC listener (`:8443` in the container) is **published directly** by Compose, not through Caddy, so mTLS is end to end.
   - TLS 1.3 only. The server certificate is issued by the DBR² CA for `DBR2_GATEWAY_HOSTNAMES` (plus the public address and the container hostname), valid 30 days, and rotated automatically a week before expiry.
10. **Worker → gateway control channel.**
    - An internal gRPC listener (`:9090`), not published, authenticated with a shared **internal token** (`DBR2_INTERNAL_TOKEN[_FILE]`, generated by `init-secrets.sh`, at least 32 characters, constant-time comparison).
    - mTLS for this hop is a later hardening step if the control plane ever spans hosts.

## Consequences

- A leaked registration token lets its holder enroll exactly one host, which then waits for approval: an administrator reviewing pending hosts closes the gap.
- The dev and test flow uses the same code paths as production. The gateway integration tests cover wrong-pin rejection, token reuse, pending rejection, approval, renewal with revocation of old certificates, suspension, revocation, a missing client certificate, and a protocol mismatch.
- `DBR2_SECRET_KEY` becomes critical for the CA as well as TOTP seeds; ADR-0008 escrow must cover it.
